# 星屑物语 · 多人联机服务端设计

> 目标：让《星屑物语 · 樱之境》（three.js 单文件客户端）支持线上多人同世界游玩。
> 技术栈：Bun + 原生 WebSocket（与现有 `bun run build.js` 工具链一致，零外部依赖）。

## 1. 现状与约束

- 客户端为纯单机：玩家状态 `P`（位置/速度/体力/星屑）、任务 `Q`（stage 0–5）、史莱姆与史莱姆王、NPC 对话、滑翔/游泳，全部本地模拟。
- 世界 800×800（`HALF=400`），地形高度/碰撞为客户端确定性算法（`world.heightAt / groundAt / Colliders`）。
- 角色系统部件化（`buildCharacter(opts)` + `animate(dt, s)`），可直接复用渲染远端玩家。
- 打包产物是单个自包含 `index.html`，服务端方案必须保持该形态（客户端只加一个 WS 连接层，不引入构建依赖）。

## 2. 总体架构

```
浏览器客户端 (index.html)
   │ wss:// … /ws  (JSON 文本帧)
   ▼
Bun Server (server/index.js)
   ├─ httpServe        静态托管 index.html + ws upgrade（同端口部署）
   ├─ RoomManager      房间 = 一个 800×800 世界实例；满员自动开分线 (lane)
   ├─ EntityRegistry   在线玩家表：id, name, look, transform, anim, flags
   ├─ WorldSync (P2)   共享进度权威：Q.stage / 神树升级 / 史莱姆王实例 / 祭坛许愿
   ├─ Interest (AOI)   300m 半径兴趣区；P1 先全量广播（≤24 人带宽足够）
   ├─ Guard            速率限制 + 移动合理性校验（反瞬移/倍速）
   └─ Persistence      rooms.json 快照，30s 节流落盘，重启恢复世界进度
```

单进程房间制：每房间一个游戏世界状态，玩家通过 lobby 选择 `world:lane`。规模上限先按 **单房间 24 人、总服 200 并发** 设计；超出后按房间分进程（`workers` 模式），协议不变。

## 3. 权威模型：混合式（已选定）

| 状态 | 权威方 | 理由 |
|---|---|---|
| 玩家移动/跳跃/滑翔 | 客户端预测，服务器**校验** | 地形/碰撞是客户端确定性算法，搬去服务器成本高且手感发黏；休闲世界作弊风险低 |
| 玩家 HP/受击 | 客户端上报，服务器记录广播 | P1 无 PvP；P2 伤害结算转服务器 |
| 共享任务阶段 `Q.stage`、神树升级 | **服务器** | 关键剧情节点必须全局一致（一人完成国王任务，全房间推进） |
| 史莱姆王 HP/存活 | **服务器** | 世界 Boss 唯一实例，命中上报→服务器扣血→广播 `boss_state`，击杀事件触发全房间 `quest_advance` |
| 祭坛许愿/团子购买 | 服务器限次 | 防重复触发全局事件 |

服务器校验规则（Guard）：
- 移动速度 ≤ 18 u/s（冲刺+滑翔峰值约 14，留余量）；越界 → 丢弃该帧并把服务器记录位置回滚。
- 单连接入站 ≤ 40 msg/s、聊天 ≤ 1 msg/s、文本 ≤ 120 字符；超限断连 30s。
- 坐标钳制在世界范围 `|x|,|z| ≤ 420`。

## 4. 房间 / 分线生命周期

1. `hello` 进入 lobby，服务器返回房间列表（名称、在线/上限、分线）。
2. `join` 选定 `room+lane`；服务器分配 `pid`，回 `welcome`（完整快照：所有人 + 世界状态）。
3. 房间内玩家 `leave`/断线 → 槽位保留 30s（同 `token` 重连恢复，避免刷新掉线丢位置）。
4. 房间满 → `lanes+1` 新开分线；同好友总进同一 lane（`join` 带 `friend tokens`）。
5. 空房 10 分钟后回收；`world` 进度持久化不随 lane 回收丢失。

## 5. 网络协议（JSON 文本帧，字段名压短）

**客户端 → 服务器**

| `t` | 载荷 | 说明 |
|---|---|---|
| `hello` | `{v:1, tok?}` | 握手；`tok` 用于断线重连恢复槽位 |
| `join` | `{r:"sakura", l:0, p:{n, look}}` | 入房；`look` 为 `buildCharacter` 外观参数 |
| `st` | `{x,y,z,Y, a:{sp,glid,sw,air,jmp,hit,dead,atk}, ts}` | 状态流，15Hz |
| `ch` | `{m}` | 聊天 |
| `hit` (P2) | `{b:"king", d, k}` | 对共享 Boss 造成伤害上报 |
| `ask` (P2) | `{k:"altar"}` | 请求触发共享事件，服务器裁决 |

**服务器 → 客户端**

| `t` | 说明 |
|---|---|
| `welcome` | `{pid, tok, room, world:{stage, kingAlive, ...}, players:[...]}` |
| `roster` | 在线名单（进出时全量下发，含外观，简单可靠） |
| `nv` | 批量移动/动画帧 `{l:[{p,x,y,z,Y,a}]}`（单条广播消息打包 2–4 人） |
| `dead` / `hit` | 玩家状态事件（死亡广播供 P2 复活交互） |
| `msg` | 聊天 `{p, m}`，服务器附脏话过滤后文本 |
| `ws` | 世界状态快照（P2：`stage/kingHp/kingPos/altarWish`，5Hz，仅变化时发） |
| `err` | `{code}` 错误 |

带宽估算（24 人房）：23 × 15Hz × ~110B ≈ **38 KB/s 下行**、上行减半 —— 可接受；P2 引入 AOI（300m）与 delta 编码（仅变化字段）可再降 ~70%。

## 6. 插值与表现（客户端）

- 远端玩家位置向下一个快照做 120ms 延迟插值（`lerp` + 最短弧 `yaw`），速度用于步态 `lf/ls` 推算，直接喂给 `char.animate(dt, s)`。
- 外观：`look` 参数随 `join` 上报，其他端用同一 `buildCharacter` 重建（含发色/瞳色/服饰，天然一致）。
- 名字标签 = CanvasTexture Sprite；聊天时头顶冒台词泡，8s 自动淡出。

## 7. 持久化与运维

- 公网部署与一键启动见 `docs/deploy.md`（`bash deploy/start.sh -d`、systemd、Docker、TLS/反代、限额与故障排查）。
- 内置加固：全局/单 IP 在连上限、单帧上限、令牌桶速率、未握手连接回收、重连槽位 TTL、重复握手去重、gzip+ETag 静态、优雅退出。
- 观测：`/healthz`（在线/在连/TLS/运行时长）、`/rooms`（分线与成员，含 ban 标记）、`/metrics`（丢弃与拒绝计数），另有 30s 周期状态日志。
- 计划中的 `server/rooms.json`（世界进度快照）属于 P2：当前版本世界进度仍按客户端本地推进。

## 8. 实施路线

- **P1（本次原型）**：握手/入房/名单、15Hz 移动+动画同步、远端玩家渲染+插值、聊天、Guard、断线重连。
- **P2**：共享任务推进、史莱姆王世界 Boss（服务器权威 HP、跳跃/践踏事件广播、全房间击杀庆祝）、祭坛许愿多人化、NPC 对话期间的“他人可见”播报。
- **P3**：组队跟随、好友分线、可选 PvP 区、玩家间碰撞、语音气泡距离衰减、delta 编码 + AOI 扩容至 50 人/房。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 客户端移动可伪造（穿墙/瞬移） | Guard 速度+范围钳制；关键状态（Boss/任务）本就服务器权威，作弊收益有限 |
| 单进程崩溃丢进度 | rooms.json 30s 快照；重启后 `world` 状态恢复 |
| 弱网抖动 | 120ms 缓冲插值 + 快照容忍丢帧（`nv` 幂等，最新者胜） |
| 移动/桌面混玩 | 协议不含输入，仅状态流，天然跨端 |
