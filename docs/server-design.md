# 星屑物语 · 多人联机服务端设计

> 目标：让《星屑物语 · 樱之境》（three.js 单文件客户端）支持线上多人同世界游玩。
> 技术栈：Bun + 原生 WebSocket（与现有 `bun run build.js` 工具链一致，零外部依赖）。

## 1. 现状与约束

- 客户端为纯单机：玩家状态 `P`（位置/速度/体力/星屑）、任务 `Q`（stage 0–5）、史莱姆与史莱姆王、NPC 对话、滑翔/游泳，全部本地模拟。
- 世界 800×800（`HALF=400`），地形高度/碰撞为客户端确定性算法（`world.heightAt / groundAt / Colliders`）。
- 角色系统部件化（`buildCharacter(opts)` + `animate(dt, s)`），可直接复用渲染远端玩家。
- 打包产物是单个自包含 `index.html`，服务端方案必须保持该形态（客户端只加一个 WS 连接层，不引入构建依赖）。

## 2. 总体架构

```
浏览器客户端 (index.html)
   │ wss:// … /ws  (JSON 文本帧)   +  https://… /api/*  (账号，HttpOnly Cookie)
   ▼
Bun Server (server/index.js)
   ├─ httpServe        静态托管 index.html + ws upgrade + /api 账号接口（同端口部署）
   ├─ Auth (auth.js)   游客自动开号 / scrypt 密码绑定 / 会话令牌 / 登录节流
   ├─ Store (db.js)    SQLite(bun:sqlite)：账号、会话、个人进度、分线世界、碎片、留言、点赞、战绩、封禁、静音、举报
   ├─ RoomManager      房间 = 一个 800×800 世界实例；满员自动开分线 (lane)
   ├─ EntityRegistry   在线玩家表：id, acct, name, look, transform, anim, flags, ip
   ├─ WorldSync        共享进度权威：Q.stage / 史莱姆王 HP / 碎片采集 / 留言 / 许愿
   ├─ Guard            速率限制 + 移动合理性校验（反瞬移/倍速）+ 权威写入闸门
   └─ cli.js           运维命令行：封禁/解封/查档案/看举报/统计
   └─ weather.js       天气规则表（纯函数，唯一口径：客户端镜像一份）
```

单进程房间制：每房间一个游戏世界状态，玩家通过 lobby 选择 `world:lane`。规模上限先按 **单房间 24 人、总服 200 并发** 设计；超出后按房间分进程（`workers` 模式），协议不变。

## 3. 权威模型：混合式（已选定）

| 状态 | 权威方 | 理由 |
|---|---|---|
| 玩家移动/跳跃/滑翔 | 客户端预测，服务器**校验** | 地形/碰撞是客户端确定性算法，搬去服务器成本高且手感发黏；休闲世界作弊风险低 |
| 玩家 HP/受击 | 客户端上报，服务器记录广播 | 打怪的扣血由本地怪物 AI 决定，服务器只转发状态位 |
| 切磋伤害 | 客户端上报，服务器**裁决** | 双方都须开启 `pv`，同线、距离 ≤6、300ms 冷却、伤害钳到 1–24，再由服务器把 `pk` 广播给双方，并按账号记当日战绩 |
| 任务阶段 `Q.stage`、神树升级、许愿数 | **服务器**（按分线） | 关键剧情节点必须一致：只允许 `+1` 前进，跳格与回退一律拒绝并计数 |
| 史莱姆王 HP/存活 | **服务器**（按分线） | 单跳伤害封顶 `KING_HIT`、每人 0.2s 一跳；死亡与复活由服务端快照下发，客户端本地不许自行击杀（`holdKill`） |
| 星屑碎片采集 | **服务器**（按分线，整数坐标去重） | 人必须在现场 12u 内、0.4s 一跳；同一坐标一条线只算一次，重启后仍不刷新 |
| 个人进度（碎片/击败/出发/倒下/阶段） | **服务器**，按账号落库 | 换设备登录即接得上；变化即刻 `pr` 单播回本人 |
| 留言石碑与点赞 | **服务器**，按账号落库 | 见下条 Guard 规则；点赞按（作者, 点赞人, 自然日）记账，重立碑也刷不出第二颗心 |
| 身份与会话 | **服务器** | 游客自动开号（Cookie），可选绑定昵称+密码（scrypt）；封禁同时覆盖账号与其最近使用的 IP |
| 星尘余额与成长等级 | **服务器**（按账号） | 采一枚碎片 +1（细雨里 +2）、打卡一页 +2、王的一跳 +4、压一波潮 +5、流星夜许愿再 +2；练一级由 `sp` 请求、服务端扣钱，价格表随 `welcome.gear` 下发。没有身份时退化为「记在这台设备上」，绑号后凭 `sq` 认领一次 |
| 景点图鉴与成就 | **服务器**（按账号，键由客户端目录给出） | 只认格式、去重、限量（80 页）；打卡不验位置——作弊的代价只是「多记一页没人看得到的风景」，不值得用服务端复核坐标去换 |
| 外观（衣服/发色/饰品） | **服务器**存档案，广播给同线 | `look` 字段白名单 + 颜色钳制 + 至多两件饰品；**账号存过的外观优先于设备带来的**，所以换机器登录还是那一身 |
| 分线天气 | **服务器**（按分线，无人不轮转） | 客户端没有改天气的入口：`we` 只随 `ws` 下发，按 `WEATHER_MS` 自己轮转，同一条线看见同一片天空。**天也换规则**（`server/weather.js` 一处写死）：细雨里一枚碎片给 2 星尘、流星夜许愿多给 2 星尘都由服务端加发；樱吹雪托滑翔、薄雾里白鹿不惧人并替人带路，这两条归客户端手感 |
| 史莱姆潮（波次与池子） | **服务器**（按分线） | 两个人在场才开潮，池子按人头加；每一跳进池封顶 `TIDE_HIT`、每人 0.2s 一跳；打空之后由服务端给全线有身份的人各记 `TIDE_GEM` 枚星尘并广播 `td`。波次号落库，**没打完的池子不跨重启**（重启等于这一波散了） |
| 星屑弹（远程攻击） | 客户端本地结算，服务器只转发演出 | 弹的伤害走的是「玩家 HP/受击」那一行的老规矩：怪物本来就在各自客户端模拟。同线的同伴收到 `bo`（谁、朝哪儿、蓄了多满）只用来演一遍光弹，服务器不认任何伤害字段 |

服务器校验规则（Guard）：
- 位移速度 ≤ 20 u/s（冲刺+滑翔峰值约 14，留余量），并按帧间隔换算 + 8u 网络抖动容忍；越界 → 丢弃该帧（不做回滚，避免拉扯）。
- 单连接入站 ≤ 60 msg/s 连续令牌桶、聊天 ≤ 1.2 msg/s、表情 1.5s/次、标点 2.5s/次、切磋 0.3s/次；超限封 30s。
- 坐标钳制在世界范围 `|x|,|z| ≤ 420`（越界是**钳制**而非丢帧），朝向做归一化而非范围拒绝（原地转圈不应丢帧）。
- **位置重同步**：连续 3 帧被速度校验拒绝、或客户端在 `st` 里带 `rs:1`，且距上次重同步 >1.2s，则该帧直接采纳为新基准。因为客户端存在合法瞬移（死亡重生、掉出世界、切后台再回来、重连落到默认坐标），永久丢帧会让该玩家在其他所有人眼里定格在旧坐标——这就是「看不见同伴 / 同伴看不见我」的根因。重同步计入 `/metrics` 的 `resync`，`/rooms` 每人带 `rej`（连续被拒帧数）。
- 切磋结算完全在服务端：双方都必须 `pv=1`、必须同房同线、距离 ≤ 6u，伤害钳制在 `1..24`；客户端只做命中判定与预测性特效。
- 留言石碑：文本走字符白名单（中日韩文字/数字/常见标点，`<`、`>`、控制字符与表情自然被剔除）后截到 24 字；只能刻在自己服务端记录位置 14u 内；与他人石碑间距 ≥3.6u；同一人 8s 才可重刻；每线最多 40 块，按落款时间淘汰最老的。点赞要求靠近 14u、4s 冷却、不能点自己的、不能跨分线。
- 静音只屏蔽**社交信号**（说话/动作/呼叫/留言/点赞回声），不抹掉人在世界里的存在——`broadcast*` 统一按 `obj.u`（发起者账号）与 `obj.own`（对象主人账号）过滤。静音表按账号存，重开仍在。
- 账号侧：昵称走 `NAME_RE` 白名单（≤16 字，常见中日韩/数字/`-_·`）且唯一先到先得；密码 ≥6 位、scrypt+salt、校验用 `timingSafeEqual`；会话令牌只存 sha256 摘要；`/api/*` 只吃 `application/json`（跨站表单发不出这个 content-type，等于一道廉价的 CSRF 门）且请求体 ≤8KB；同一 IP 连错 5 次锁 10 分钟（正确密码也先拒，防撞库）；开号/绑定按 IP 节流。
- 封禁按**账号 + 其最近使用的 IP** 双写：只封账号的话，丢掉 Cookie 换个匿名连接就回来了。匿名连接照样能玩，但 `acct=null`：不落库、不能被静音/举报追责，也进不了被封的 IP。
- 烟花只限频率（每人 8s 一朵，越界被记进 `firework_rejected`）而不验证理由：它是纯表现层的广播，最坏结果只是这条分线的天空热闹一点。
- 星屑弹同属表现层：`bo` 只带 `c`（蓄力度，钳到 0..1）与 `Y`（朝向，钳到 ±7），坐标由服务端用它自己记录的 `p.x/p.y/p.z` 补，所以没人能替别人放弹；每人 0.35s 一发，越界记 `bolt_rejected`。客户端侧则有一条**手感硬约束**：远程攻击全程不调 `shake()`，命中只给光点与细环——这个项目的使用者会被镜头晃动晃晕。
- 潮池只认服务端那一份：`th` 的 `d` 钳到 `1..TIDE_HIT`、每人 0.2s 一跳，池子不会被打成负数，也不许在没潮的时候扣（越界记 `tide_rejected`）。开潮的条件写在世界推进的定时器里（在场且已进房的人数 ≥2），客户端没有「开潮」的入口——一个人刷不出第二个人的奖励，两个人也刷不出第三个人的。
- 天气玩法分两半，各自待在该待的地方：**要给星尘的**（雨里的碎片、流星夜的愿望）由服务端在记账时用 `shardGem(w.weather)` / `wishGem(w.weather)` 加发，客户端报不出天候；**只是手感的**（樱吹雪托滑翔、薄雾里白鹿带路）留在客户端，反正没有可骗的东西。两边都只看 `net.world.weather`（这条线实际的天），**不看设置里那个「分线天气」开关**——舒适与画质开关管的是眼睛，不该偷偷改账本与手感。表只写在 `server/weather.js`，`src/main.js` 镜像同样四个数字，`ui-wiring` 守着不许分叉。

## 4. 房间 / 分线生命周期

1. `hello` 进入 lobby，服务器返回房间列表（名称、在线/上限、分线）。
2. `join` 选定 `room+lane`；服务器分配 `pid`，回 `welcome`（完整快照：所有人 + 世界状态）。
3. 房间内玩家 `leave`/断线 → 立即广播 `gone`；`token` 目前只用于 `pending`（握手后未入房）槽位的 30s 回收。**注意：断线重连会拿到新的 `pid`**，其他人看到的是「离开→重新加入」；位置由客户端首帧的 `rs` 重同步纠正，不会定格在旧坐标。跨重连保位（seats 表）留到 P2。
4. 房间满 → `lanes+1` 新开分线；同好友总进同一 lane（`join` 带 `friend tokens`）。
5. 空房 10 分钟后回收；`world` 进度持久化不随 lane 回收丢失。

## 5. 网络协议（JSON 文本帧，字段名压短）

**客户端 → 服务器**

| `t` | 载荷 | 说明 |
|---|---|---|
| `hello` | `{v:1, tok?}` | 握手；`tok` 用于断线重连恢复槽位 |
| `join` | `{r:"sakura", l:0, p:{n, look}}` | 入房；`look` 为 `buildCharacter` 外观参数。带 `aw_sid` Cookie 时按账号认定身份、回灌进度 |
| `st` | `{x,y,z,Y, rs?, a:{sp,glid,sw,air,jmp,hit,dead,atk}, ts}` | 状态流，15Hz；`rs:1` 请求重同步位置（重生/传送后用） |
| `ch` | `{m}` | 聊天 |
| `pv` | `{v:0|1}` | 切磋开关：只表达本人意愿，服务端记账后广播 |
| `em` | `{e:"wave\|heart\|up\|spark\|bow\|dance"}` | 友好动作，白名单外丢弃，1.5s 冷却 |
| `pk` | `{k:<目标id>, d:1..24}` | 切磋命中上报，是否结算由服务端裁决 |
| `pg` | `{x,z}` | 地图标点呼叫，2.5s 冷却 |
| `fw` | `{x,z}` | 放一朵给同线所有人的烟花，坐标取整，8s 一朵 |
| `mb` | `{x,z,s}` | 刻/挪留言石碑，`s` 由服务端白名单过滤后截到 24 字 |
| `mx` | `{}` | 收回自己的石碑 |
| `ml` | `{p:<石碑主人账号>}` | 给靠近的留言点心，4s 冷却 |
| `qs` | `{st?,k0?,wi?,up?,de?}` | 权威进度上报：阶段/击杀基准/许愿数只认 `+1`；`up` 神树强化；`de` 只记本人倒下次数 |
| `tk` | `{x,z}` | 采集星屑碎片（服务端按整数坐标去重，须在 12u 内，0.4s 一跳） |
| `kb` | `{d}` | 对史莱姆王的一跳伤害，封顶 `KING_HIT`、0.2s 一跳 |
| `th` | `{d}` | 对潮水的一跳伤害：投进这条分线共用的池子，封顶 `TIDE_HIT`、0.2s 一跳；没潮时只计数 |
| `bo` | `{c,Y}` | 星屑弹的演出广播：蓄力度 0..1 + 朝向，坐标取服务端记录的那一份；每人 0.35s 一发 |
| `sp` | `{k:"vit\|jump\|glide\|dmg\|shot"}` | 想把某条成长线练一级：客户端只报意愿，**星尘余额与等级都只在这里变动**（300ms 一跳，钱不够/已满级则原样回灌 `pr`） |
| `sq` | `{gem,gear,stamps}` | 认领「这台设备上单机攒下的成长」：仅当账号确实一片空白时接受，余额与等级一律按上限收，图鉴记录只搬账不重发星尘 |
| `cd` | `{s:"village"}` | 景点打卡/成就：键须匹配 `^[a-z][a-z0-9_]{1,23}$`，去重、上限 80 页，第一次给 2 星尘，600ms 一跳 |
| `lk` | `{look}` | 换装：字段与颜色由服务端清洗（`look` 六色 + 发型白名单 + 至多两件饰品），当场广播给同线同伴并写回账号 |
| `mu` | `{u, on}` | 屏蔽/解除屏蔽某账号的社交信号（需自己有身份） |
| `rp` | `{u, r}` | 举报（落库供 `cli.js reports` 人工处理） |
| `leave` / `ping` | `{}` / `{ts}` | 退房（顺带落一次档案）/ 心跳 |

**服务器 → 客户端**

| `t` | 说明 |
|---|---|
| `welcome` | 进房全量快照：`{pid, tok, room, lane, pv, me:{a,n,bound}\|null, prog, pvp, look, gear, gemCost, world:{...ws}, shards:[[x,z]], boards:[...], players:[...]}`（`gear` 是成长表定义本身——价格只在服务端写一处） |
| `roster` | 在线名单（进出时全量下发，含外观与账号 `u`，简单可靠） |
| `nv` | 批量移动/动画帧 `{l:[{p,x,y,z,Y,a}]}`（单条广播消息打包 2–4 人） |
| `gone` | 某人离开 `{p}` |
| `msg` | 聊天 `{p, u, n, m}`，服务器附脏话过滤后文本 |
| `pv` | 切磋开关变更 `{p, v}`（含发起者自身，重连/换线后据此对齐；客户端屏蔽自己的回声） |
| `em` | 友好动作 `{p, e}`，仅广播给他人 |
| `pk` | 切磋结算 `{a, s, d, x, z}`：双方与同线可见，`d` 为服务端钳制后的伤害 |
| `pg` | 地图标点 `{p, n, x, z}`，不回传给发起者 |
| `mb` | 留言石碑 upsert `{u, own, p, x, z, s, by, l}`，含发起者自己（`p` 为石碑主人**账号**，匿名时退化为连接 id） |
| `md` | 某人收回石碑 `{p}` |
| `ws` | 分线权威世界快照 `{st, k0, ka, kh, km, wi, up, we, tr, ta, th, tm}`，5Hz 且仅变化时发（`km` 为王血量上限，客户端据此换算血条；`we` 为这条分线的天气编号；`tr/ta/th/tm` 为潮的波次号/是否在打/当前池子/本波上限） |
| `sk` | 碎片被采走 `{x, z, c, n}`（`c` 为本线已采总数），同线含发起者都收到 |
| `lk` | 某人换装 `{p, look}`，只广播给他人，不回传发起者 |
| `fw` | 有人放烟花 `{p, n, x, z}`，不回传发起者（本地已先响一声） |
| `bo` | 有人放星屑弹 `{p, c, Y}`，不回传发起者：客户端按 `c` 决定弹体大小与颜色，纯演出不带伤害 |
| `td` | 这一波潮被压下去了 `{r:波次号, g:每人所得星尘}`，全线都收到（含发起者，因为奖励是大家的） |
| `pr` | **单播给本人**的个人档案变化 `{prog}`，避免面板停在进房那一刻 |
| `err` | `{code:"full\|rate\|banned", until?}` |
| `pong` | 心跳回执 `{ts}` |

账号接口（HTTP，同源，`SameSite=Lax + HttpOnly` Cookie `aw_sid`）：`GET /api/me`、`POST /api/guest`（幂等，刷新页面不会又开一个号）、`POST /api/login {n,p}`、`POST /api/bind {n,p}`、`POST /api/logout`。密码学校验是异步的（scrypt），故这些处理器是 `async`。

带宽估算（24 人房）：23 × 15Hz × ~110B ≈ **38 KB/s 下行**、上行减半 —— 可接受；P2 引入 AOI（300m）与 delta 编码（仅变化字段）可再降 ~70%。

## 6. 插值与表现（客户端）

- 远端玩家位置向下一个快照做 120ms 延迟插值（`lerp` + 最短弧 `yaw`），速度用于步态 `lf/ls` 推算，直接喂给 `char.animate(dt, s)`。
- 外观：`look` 参数随 `join` 上报，其他端用同一 `buildCharacter` 重建（含发色/瞳色/服饰，天然一致）。
- 名字标签 = CanvasTexture Sprite；聊天时头顶冒台词泡，8s 自动淡出。
- **预测与权威的分界**：本地立刻出伤害数字/血条/拾取动画，但结论以服务端为准——王血每帧用 `ws` 的 `kh/km` 覆盖本地值，且联机时 `holdKill` 不允许本地把王打死（否则一个人改内存就能把整条分线的剧情推走）；碎片以 `taken` 集合（`welcome.shards` 全量 + `sk` 增量）为准，已采的不再出现。
- 面板（`P` 键 / 档案胶囊）：显示身份、绑定状态、个人档案与本线世界进度；游客号在页面一开就静默开好，玩家不点任何东西也在落库。旅伴名单里有身份者可一键屏蔽/举报（举报借用聊天输入框写理由）。

## 7. 持久化与运维

- 公网部署与一键启动见 `docs/deploy.md`（`bash deploy/start.sh -d`、systemd、Docker、TLS/反代、限额与故障排查）。
- **存储**：`AW_DB=/var/lib/anime-world/world.db`（`bun:sqlite`，WAL + busy_timeout）。没设或打不开时自动退回内存模式（`/healthz` 的 `db` 字段为 `memory`，联机照常，只是不跨重启）。建表幂等，列变更走 `MIGRATE` 的 `alter table add column` + try/catch，老库文件可直接升级。
- **运维 CLI**：`bun server/cli.js ban <账号|昵称> [分钟] [备注]` / `unban` / `bans` / `who <账号|昵称>` / `accounts [N]` / `reports` / `stats` / `mute` / `unmute`，直接读写同一个 `AW_DB`（需显式设置该环境变量）。
- 内置加固：全局/单 IP 在连上限、单帧上限、令牌桶速率、未握手连接回收、重连槽位 TTL、重复握手去重、gzip+ETag 静态、优雅退出、登录失败锁定、开号/绑定节流、封号连带最近 IP。
- 观测：`/healthz`（在线/在连/TLS/运行时长/`db`/`db_file`/账号·会话·留言·碎片·举报计数）、`/rooms`（分线与成员，含 ban 与连续被拒帧数 `rej`）、`/metrics`（`drops rejected pvp_rejected resync world_rejected take_rejected king_rejected like_rejected gear_rejected codex_rejected firework_rejected bolt_rejected tide_rejected tides msg_out`，其中 `tides` 是正在打潮的分线数），另有 30s 周期状态日志。
- 回归测试（`bun test/run-all.mjs`，全部并发、各自独占端口，约 14s）：`net-smoke`（协议与 Guard）、`net-client`（真实 `src/net.js` + 扮演队友）、`hardening`（公网加固边界）、`account`（HTTP 账号 + 权威 + 重启留存 + CLI 封禁）、`db-auth`（纯逻辑）、`ui-wiring`（静态接线，含每个 `$()` id 是否真存在于模板）、`ui-probe`（headless Chrome 走玩家真实路径：游客号 Cookie → 绑定 → 进度回灌 → 退出 → 登录找回同一个号）。测试用的服务端一律 `PORT=0` 由系统挑端口并从 `AW_PORT_FILE` 读回，`/healthz` 缺少 `db` 字段即判定为上一轮遗留进程并报错。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 客户端移动可伪造（穿墙/瞬移） | Guard 速度校验 + 现场距离校验（采碎片、刻碑、点赞都要人在服务端记录的位置旁）；剧情/王血/碎片本就服务端权威，改本地内存收益有限 |
| 单进程崩溃丢进度 | 世界进度按分线脏标记落 SQLite（5Hz 合并写），个人档案每次变化即写；重启后 `welcome` 回灌，实测碎片仍不可重复采集 |
| 弱网抖动 | 120ms 缓冲插值 + 快照容忍丢帧（`nv` 幂等，最新者胜），上行队列有上限且丢最老的 |
| 匿名连接绕过封禁 | 封号连带其最近使用的 IP；无 Cookie 连接虽可玩但不落库、不可追责 |
| 密码库外泄 | 库里只有 scrypt 摘要与 salt，会话令牌只存 sha256；凭据走 HttpOnly Cookie，脚本读不到 |
| 无 TLS 时凭据明文过网 | `ws://`/`http://` 下 Cookie 不是 `Secure`，公网正式运营前必须上反代证书（见 `docs/deploy.md`） |
